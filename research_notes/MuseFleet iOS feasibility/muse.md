# Meta Muse: official website, iOS login, observable events and notification upstreams

Research date: **2026-11-28**. All retrieval dates below are 2026-11-28 unless stated otherwise. Scope: public official pages, unauthenticated HTTP HTML, Apple platform documentation and public search discovery. No browser MCP, JavaScript execution, login, credentials, private API requests, session extraction, Apple build or device tests were used. The research assignment and this worktree's AGENTS.md govern the implementation recommendations.

Classification vocabulary: **VERIFIED** = directly observed in the fetched public response; **DOCUMENTED** = a statement in fetched official documentation/listing, without runtime verification; **UNVERIFIED** = evidence or a necessary runtime test is missing; **UNSUPPORTED** = the particular proposed mechanism/guarantee conflicts with the cited platform contract, not a blanket claim that Meta prohibits an integration; **BLOCKED** = this research method could not obtain the necessary content/access. Search snippets were discovery aids only, never the sole evidence for a product capability. A missing search result does not establish that a feature does not exist.

## 1. Which website and login flow are established, and does iOS 17 WKWebView work?

### Takeaway

**VERIFIED:** `https://muse.ai/` currently serves Meta's personal AI agent landing page and an inline email/mobile-number login form. **UNVERIFIED:** successful authentication and ongoing operation inside a third-party WKWebView on iOS 17; the official native Muse app currently **documents iOS 18.0+**, while Apple's separate persistent profile data-store API is **documented from iOS 17.0**. [Muse HTML](https://muse.ai/); [official Muse getting-started guide](https://www.meta.com/help/superintelligence/1331373868832401/); [Meta's App Store listing](https://apps.apple.com/us/app/muse-from-meta/id6760173601); [Apple data-store documentation JSON](https://developer.apple.com/tutorials/data/documentation/webkit/wkwebsitedatastore/init(foridentifier:).json)

### Cited Findings

- **VERIFIED — official entry point:** the fetched home HTML has title `Muse — Your Personal AI Agent from Meta`, canonical URL `https://muse.ai/`, Meta branding and `© Meta 2026`. Meta's own Help Center links to the Muse product, its privacy policy and terms at `muse.ai`; the App Store listing identifies the seller as **Meta Platforms, Inc.** and links its developer website to `https://muse.ai`. These independent official cross-links support the domain attribution. [Muse HTML](https://muse.ai/); [Meta email documentation](https://www.meta.com/help/superintelligence/1149305437517250/); [App Store](https://apps.apple.com/us/app/muse-from-meta/id6760173601)
- **VERIFIED — second initial URL, limited body:** fetching `https://ai.meta.com/muse/` returned Meta navigation and Muse download links to `https://applink.muse.ai/` with campaign parameters. Its extracted response did not expose the full product article. It establishes an official Muse link, not authenticated app behavior or a conversation deep-link scheme. The more complete public product evidence in this run is the fetched `muse.ai` HTML. [AI at Meta Muse page](https://ai.meta.com/muse/); [Muse HTML](https://muse.ai/)
- **DOCUMENTED — availability:** the Muse Help Center says the app and website are not yet available everywhere and individual features may be unavailable by area. It does not establish that this user's country or accounts are eligible. [Muse Help Center](https://www.meta.com/help/superintelligence/1303670544995562/)
- **DOCUMENTED — identity:** the getting-started guide says both app and web use a Meta Account; one can create an account with an existing Facebook/Instagram account or an email address/phone number. It displayed `Updated: 2 days ago` at retrieval; that is a relative publisher label, not a verified exact publication timestamp. [Getting started](https://www.meta.com/help/superintelligence/1331373868832401/)
- **VERIFIED — initial login DOM only:** the public page contains a heading `Log in or create an account`, an input with `aria-label="Mobile number or email"`, `autocomplete="username webauthn"`, `inputmode="email"`, and a disabled `Continue` submit button. It also warns that using a mobile number may result in SMS notifications. This proves only the initial public form; it does not prove the next password, OTP, passkey, federation or recovery steps. No form was submitted. [Muse HTML](https://muse.ai/)
- **DOCUMENTED — official native iOS requirement:** the US App Store page says `Requires iOS 18.0 or later`, with seller Meta Platforms, Inc. and version `17.0` displayed as `2d ago`. An app version of 17.0 must not be confused with an iOS 17 requirement. This is a listing observation, not installation or execution evidence. [App Store](https://apps.apple.com/us/app/muse-from-meta/id6760173601)
- **DOCUMENTED — iOS 17 account-store primitive:** Apple's public DocC JSON for `WKWebsiteDataStore.init(forIdentifier:)` says it returns a persistent store for a supplied UUID, creates it if absent, and should be used for a profile. Platform metadata specifies introduction in iOS/iPadOS **17.0**. The same document describes WKWebsiteDataStore as managing cookies, disk/memory caches and other web-view data. This supports the project's one-UUID-per-account architecture, without establishing Muse authentication compatibility. [Apple canonical reference](https://developer.apple.com/documentation/webkit/wkwebsitedatastore/init(foridentifier:)); [actually fetched Apple JSON](https://developer.apple.com/tutorials/data/documentation/webkit/wkwebsitedatastore/init(foridentifier:).json)

### Inferences

- **UNVERIFIED — embedded login:** neither fetched Muse documentation nor the targeted `"Muse" "WKWebView" login` search yielded an official third-party WKWebView compatibility commitment. Do not report either “works on iOS 17” or “Meta blocks WKWebView” as established. Public HTML retrieval is not a Safari/WKWebView compatibility test. [Getting started](https://www.meta.com/help/superintelligence/1331373868832401/); [public initial form](https://muse.ai/)
- **Recommendation:** start at the verified HTTPS home URL with `WKWebsiteDataStore(forIdentifier: account.id)`, as required by AGENTS.md. Let the person complete the official website flow inside the isolated browser UI. Do not copy a Safari/external-browser session into that store, intercept credentials, or assume an external login has authenticated the WKWebView. The data-store primitive is documented; the Muse end-to-end flow still needs testing. [Apple data-store contract](https://developer.apple.com/tutorials/data/documentation/webkit/wkwebsitedatastore/init(foridentifier:).json); [Meta web-account guidance](https://www.meta.com/help/superintelligence/1331373868832401/)
- **Recommendation:** use an exact host allowlist derived from verified navigation, with HTTPS, no URL credentials and no nonstandard ports. Only the root `muse.ai` app entry was directly inspected here; `applink.muse.ai` was observed as an official download link, not independently followed or verified as a chat destination. Meta documentation also mentions `www.muse.ai`, but this run did not independently fetch that host. None justifies accepting every `*.muse.ai` host or treating Meta help/download links as conversation URLs. [Muse HTML](https://muse.ai/); [AI at Meta link](https://ai.meta.com/muse/); [account-contact documentation](https://www.meta.com/help/artificial-intelligence/31983416211257755/)

### Gaps

- **UNVERIFIED:** web login and chat compatibility on iOS 17, iOS 18, real-device Safari and a third-party WKWebView; persistence across restart; logout isolation; two simultaneous account profiles; popups, redirects, passkeys, recovery and expiry flows. These require user-controlled official login and real device testing; no credentials are needed in research notes or logs. The public form and Apple's data-store documentation alone cannot answer them. [Muse HTML](https://muse.ai/); [Apple profile data stores](https://developer.apple.com/tutorials/data/documentation/webkit/wkwebsitedatastore/init(foridentifier:).json)
- **UNVERIFIED:** Meta's specific acceptance/policy for this third-party account-switching wrapper and any account-count restrictions. The fetched help pages describe official Muse use, without a third-party wrapper support commitment. Do not convert this gap into an invented ban or authorization. [Getting started](https://www.meta.com/help/superintelligence/1331373868832401/)

## 2. Can conversation URLs and message/task completion be detected from the UI?

### Takeaway

**BLOCKED:** authenticated conversation DOM and runtime navigation were unavailable to this unauthenticated HTTP-only research. **UNVERIFIED:** conversation path patterns, stable message IDs and every completion/approval/error selector. There are real public landing/login selectors, listed below, but none detects authenticated task completion. Meta explicitly documents that Muse is **not turn-by-turn**, which makes a simple “assistant stopped typing” rule especially unreliable. [Public HTML](https://muse.ai/); [getting-started guide](https://www.meta.com/help/superintelligence/1331373868832401/)

### Cited Findings

- **DOCUMENTED — asynchronous conversations:** Meta says users need not wait for a response before asking another question; “Unlike other AI apps, Muse is not turn-by-turn.” It also documents main chat and separate side chats, with awareness across chats. This documents UI concepts, not stable URL routes or event identifiers. [Getting started](https://www.meta.com/help/superintelligence/1331373868832401/)
- **DOCUMENTED — artifacts and approval:** finished artifacts are saved in Library and shared in the conversation. The landing page says users approve actions such as sending emails/purchases and can see an audit trail. Neither fetched page provides the authenticated HTML representation, a machine-readable state transition or a selector contract for those events. [Getting started](https://www.meta.com/help/superintelligence/1331373868832401/); [Muse HTML](https://muse.ai/)
- **VERIFIED — real static public selectors:** the following strings are present in the unauthenticated HTTP response, before browser hydration. They were inspected as source HTML; no querySelector execution, uniqueness test, iOS rendering or long-term stability test was performed. [Fetched public HTML](https://muse.ai/)

| Selector seen in public HTML | Observed element/state | Classification and allowable conclusion |
| --- | --- | --- |
| `div[role="region"][aria-label="Muse landing page"]` | Public landing scroll region | **VERIFIED** landing region only. |
| `h1#landing-hero-title` | `Muse, AI that gets it done for you` | **VERIFIED** public page heading, not chat status. |
| `section[data-testid="native-auth-access-pane"]` | Inline account/login entry pane | **VERIFIED** public login container, not a documented stable API. |
| `section[data-testid="native-auth-access-pane"] input[aria-label="Mobile number or email"]` | Empty initial login field | **VERIFIED** field presence; never collect its value. |
| `section[data-testid="native-auth-access-pane"] button[type="submit"]` | `Continue`, initially disabled | **VERIFIED** initial submit control only; no submission performed. |
| `section[aria-label="Notifications alt+T"][aria-live="polite"]` | Empty section, also `aria-relevant="additions text"` and `aria-atomic="false"` | **VERIFIED** empty live region. No evidence its content represents Muse replies, native notifications or completed tasks. |

- **VERIFIED — misleading generic state exists on landing:** public feature media placeholders include `aria-busy="true"`. Therefore `aria-busy`, a generic live region, a visible animation or an element containing “done” is not by itself evidence of a completed assistant task. The public headline itself includes “gets it done for you.” [Muse HTML](https://muse.ai/)
- **UNVERIFIED — conversation URLs:** no authenticated conversation URL, main-chat route, side-chat route or official conversation deep-link specification was obtained. The only directly verified app entry is `https://muse.ai/`; the `applink.muse.ai` URLs observed on Meta's page are download links. Do not invent `/chat/<id>`, `/c/<id>`, `/conversation/<id>` or any ID shape. [Muse HTML](https://muse.ai/); [AI at Meta page](https://ai.meta.com/muse/); [side-chat instructions](https://www.meta.com/help/superintelligence/1331373868832401/)

### Inferences

- **UNVERIFIED — all production observer event types:** there is no verified authenticated mapping for `response`, `completed`, `failed`, `attention`, `approval`, `question`, `artifact`, `progress` or `sessionExpired`. Keep a site-specific observer unavailable until actual rendered Muse UI evidence establishes selectors and state transitions. A generic MutationObserver or a synthetic fixture validates plumbing only. It does not establish Muse support. [Public HTML boundary](https://muse.ai/); [official asynchronous conversation model](https://www.meta.com/help/superintelligence/1331373868832401/)
- **Recommendation:** distinguish **new assistant response** from **task completed**. Text becoming stable, an animation disappearing or a response ending can occur before a continuing task, an approval or a later proactive update. This is an engineering inference from Meta's asynchronous/non-turn-by-turn model, not a reverse-engineered observation of Muse internals. [Getting started](https://www.meta.com/help/superintelligence/1331373868832401/); [official ongoing-task product description](https://apps.apple.com/us/app/muse-from-meta/id6760173601)
- **Recommendation:** when authenticated testing becomes available, record only a sanitized description of rendered element roles/attributes and the final allowed navigation URL, after explicit user control of the account. Establish message identity, overlapping tasks, streamed edits, reload deduplication and side-chat switching before mapping events. Do not inspect authentication storage, network internals or private APIs. The need for these checks follows from separate side chats and overlapping user input. [Getting started](https://www.meta.com/help/superintelligence/1331373868832401/)
- **Recommendation:** a notification may omit its conversation URL and route to the correct account's verified home until a real allowed conversation URL exists. A fabricated path is weaker than a safe account-level fallback. This recommendation reflects the current URL evidence gap. [Verified home](https://muse.ai/); [documented chat concepts without route specification](https://www.meta.com/help/superintelligence/1331373868832401/)

### Gaps

- **BLOCKED:** rendered authenticated message/approval/task DOM, task lifecycle transitions and real task-linked URLs; HTTP fetches returned the public landing/login experience and no account was used. The absence of authenticated evidence is not evidence that a corresponding UI does not exist. [Observed page](https://muse.ai/)
- **UNVERIFIED:** web Notification API prompts, service-worker push support, badge behavior, browser notification settings, stable public DOM contracts, cross-chat event IDs and whether all task events appear in a foreground chat. The fetched product/help pages do not specify these interfaces. [Help Center](https://www.meta.com/help/superintelligence/1303670544995562/); [public page](https://muse.ai/)

## 3. What official notifications, email, WhatsApp or webhooks can feed MuseFleet and a relay?

### Takeaway

**DOCUMENTED:** the official Muse app advertises notifications when attention is needed; Meta documents conversation reminders, email/SMS account notifications, agent email and WhatsApp chat. **UNVERIFIED:** a Muse event webhook, a complete completion-email feed, or permission to consume/forward all Muse WhatsApp events. A relay can transport an event only after a permitted, reliable **upstream event source actually exists**; APNs implementation cannot create missing Muse task events. [App Store](https://apps.apple.com/us/app/muse-from-meta/id6760173601); [reminders](https://www.meta.com/help/superintelligence/1484325780075655/); [account notifications](https://www.meta.com/help/artificial-intelligence/31983416211257755/); [agent email](https://www.meta.com/help/superintelligence/1149305437517250/); [WhatsApp product statement](https://muse.ai/); [actually fetched Apple APNs documentation](https://developer.apple.com/tutorials/data/documentation/usernotifications/sending-notification-requests-to-apns.json)

- **DOCUMENTED — APNs requires an existing payload and authenticated sender:** Apple's fetched DocC JSON says that **when you have a notification to send**, a provider constructs an authenticated POST with a device token and JSON payload. `apns-topic` normally identifies the app's bundle ID; authentication authorizes the topic. ### Inferences

- **UNSUPPORTED — receiving Meta's pushes merely by registering MuseFleet with APNs:** MuseFleet's APNs token/topic and provider authorization do not subscribe it to another app's notification feed. A supported Meta integration would have to deliver an event to MuseFleet's authorized provider path. This follows from Apple's app-topic/device-token/authentication contract; no such Muse integration was established here. [Apple APNs contract](https://developer.apple.com/tutorials/data/documentation/usernotifications/sending-notification-requests-to-apns.json); [official Muse notification claim](https://apps.apple.com/us/app/muse-from-meta/id6760173601)
- **UNSUPPORTED — guaranteed APNs delivery:** claiming 100% delivery, exact order or always-immediate alerts directly conflicts with Apple's best-effort documentation. [Apple APNs documentation](https://developer.apple.com/tutorials/data/documentation/usernotifications/sending-notification-requests-to-apns.json)
- **Recommendation — upstream must come first:** the required chain is **permitted Muse event source → account/event identification → authorized relay → MuseFleet APNs payload → validated account route**. The unproven link today is the first one. Deploying a relay, acquiring a domain or paying for a server does not supply Muse completion events. This is an architectural inference from the missing Muse event interface and APNs's requirement for an already-known payload. [Current official Muse entry/documentation](https://www.meta.com/help/superintelligence/1303670544995562/); [Apple provider requirements](https://developer.apple.com/tutorials/data/documentation/usernotifications/sending-notification-requests-to-apns.json)
- **Recommendation — evaluate channels separately:** a user-authorized email experiment must prove that the desired event is emitted consistently, identifies the correct account/task, includes a safe URL if needed, survives retries and excludes authentication messages. WhatsApp support must independently establish permitted export/receipt before any relay plan. Official end-user channel availability is not proof of a programmatic lifecycle feed. [Muse email behavior and limits](https://www.meta.com/help/superintelligence/1149305437517250/); [account/safety notification purposes](https://www.meta.com/help/artificial-intelligence/31983416211257755/); [WhatsApp product statement](https://muse.ai/)
- **Recommendation — accurately scope foreground observations:** a future verified foreground DOM observer can feed local account events while its page is active. Meta's cloud-agent/official-app “keeps working” statements do not establish continuous background execution for MuseFleet's embedded web views. No 24/7 monitoring, background WebView polling or official remote-event capability should be claimed from this research. [Muse's own cloud-computer description](https://muse.ai/); [official-app product claim](https://apps.apple.com/us/app/muse-from-meta/id6760173601)

### Gaps

- **UNVERIFIED / release blocker:** real iOS 17 WKWebView login and isolated multi-account persistence. Apple supports the store API; Muse compatibility and account eligibility still need execution evidence. [Apple profile store](https://developer.apple.com/tutorials/data/documentation/webkit/wkwebsitedatastore/init(foridentifier:).json); [Muse availability](https://www.meta.com/help/superintelligence/1303670544995562/)
- **BLOCKED / release blocker:** no authenticated conversation DOM or URL evidence, so no production completion/approval selectors are available. A local synthetic fixture cannot close this gap. [Observed public-only page](https://muse.ai/); [documented asynchronous chat](https://www.meta.com/help/superintelligence/1331373868832401/)
- **UNVERIFIED / notification blocker:** no proven permitted upstream that exports desired Muse events outside a loaded foreground page. Until one is established, a remote notification relay is a transport proposal without its required input. Official Muse app alerts, agent email and WhatsApp chat alone do not close that gap. [Official app](https://apps.apple.com/us/app/muse-from-meta/id6760173601); [email](https://www.meta.com/help/superintelligence/1149305437517250/); [WhatsApp statement](https://muse.ai/); [APNs requirements](https://developer.apple.com/tutorials/data/documentation/usernotifications/sending-notification-requests-to-apns.json)
- **Not performed:** authenticated website interaction, device/Safari/WKWebView tests, real notification/email/WhatsApp delivery, Xcode builds, background runtime measurements or any relay deployment. Documentation and public-response checks are the entire evidence basis of this note; none of those execution checks is marked passed.
